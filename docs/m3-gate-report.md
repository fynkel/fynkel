# M3 gate report and go/no-go

**Date:** 2026-09-22 · **Milestone:** M3 (blueprint §16 "M3 — Code-first reference game, Tier 1") · **Verdict: GO with two named exceptions — proceed; the repository stays private.**

M3 asked whether a game can be built on Fynkel from code alone: a renderer
that draws thousands of objects, physics, a character, input, audio,
scenes, prefabs, Flutter HUD and world labels, settings, headless tests,
and a reference game that uses all of it — with no editor in the way. The
backlog (§19.2d) landed one commit per item, 33 `M3-NN` commits between
`b35f603` (2026-09-19) and `6176d5e` (2026-09-22); this report is item 18,
written short by the user's call (the engine matters more than its
paperwork while nobody else reads it). Everything below is reproducible
from a clean clone with `docs/status.md` §5; the captures are
`benchmarks/m3/results/2026-09-22-871c353.md` and
`benchmarks/m0/results/2026-09-22-871c353.md` (profile `mac-m3max-2026`).

No hard-kill criterion was hit. The "do not" list held with one deliberate
breach: skinning and animation, listed as Tier 2 → M5, were pulled into
M3 as item 19 (the user's call on 2026-09-20: a Mixamo character is what a
code-first developer tries first, and the core had to hold it); the
`WorldCanvas` and spatial audio stay in M5. No speculative system was added
to make the demo impressive — the reference game is the §1.2 spec at Tier
1 plus the animated player — and no usability problem was postponed to the
editor (the `find`/`instantiate`/temp-reference ergonomics of M3-08b, the
typed component path of M3-07a, the settings store, the input recordings
all came from building the game without one).

## 2. What M3 delivered

One reference per area; the documents are the contract.

- **Renderer V1** (`docs/renderer.md`, M3-04/05/06): PBR with every map,
  HDR + ACES + exposure, sun/ambient/sky, 8 point/spot lights, the sun's
  PCF shadow, transparency, MSAA and render scale, quality profiles at
  runtime, debug lines; one draw per `(mesh, material)` pair with
  instancing and frustum culling; 14 pipeline variants with skinning; the
  showcase scene (`examples/showcase`, `renders/`) every item is looked at
  through.
- **Physics** (`docs/physics.md`, M3-08/09): Rapier bodies and colliders
  as ordinary native components, the §5.1 step slot, body commands,
  contacts and triggers on behaviours, raycast/shape-cast/overlap, the
  kinematic character controller and the third-person camera rig.
- **Input** (`docs/input.md`, M3-07): named actions from the project
  file, the held/edge rules in the core, keyboard/mouse/gamepad/touch
  overlay through Flutter, recordings replayed headlessly and in tests.
- **Audio** (`docs/audio.md`, M3-11): `cpal` + Fynkel's own mixer, three
  buses, one-shots and streamed music, the device lifecycle through the
  ABI.
- **Scenes, zones, settings** (`docs/scenes.md`, M3-12): replace/additive
  loads and unloads at the next frame, trigger zones, the settings
  document behind `GameContext.settings`.
- **HUD and world labels** (`docs/hud.md`, M3-13): `GameModel`/`ModelValue`
  bound into Flutter, the bounded projection view, `ProjectionLayer`.
- **The native catalogue** (`docs/catalogue.md`, M3-10): six movers and
  emitters ticked by the core with per-system time.
- **Animation** (`docs/animation.md`, M3-19/19a/19b/19c): clips, skins,
  crossfades, blend spaces, layers, markers, root motion; glTF and FBX
  import, prefab instancing of an imported hierarchy, the rig document.
- **The SDK** (`docs/design/dart-sdk.md`): typed native components from
  Dart, `find`/`instantiate`/spawn-then-configure in one tick, the
  read-path allocation work of M3-16c.
- **Tooling** (`docs/how.md`, `docs/hosts.md`): `fynkel create`, `run`,
  `test --headless` with recordings and `--json`, `render`, `import
  --prefab/--rig`, the stress generator, the captures.
- **The reference game** (`examples/reference_game`, M3-14/15): three
  scenes, four behaviours, the recorded route, menus, pause, results,
  settings, sound — CI regenerates, validates, replays and tests it.

## 4. Deviations from the backlog, decided

- **The C ABI stays at version 1.** §19.2d said the M3 gate bumps
  `FYNKEL_ABI_VERSION` once for the additive entry points of M3. Nothing
  outside this checkout links the library, every addition was additive
  (the viewport ABI carries its own version, 4, and the authoring ABI its
  own, 3), and a bump touches every project lock and the editor's
  fixtures across the two branches. It is deferred to the first external
  consumer — the "public readiness (b)" item — where a version means
  something.
- **Item 17 thin, no iPhone** — above.
- **Animation in M3** — above. Its Tier 2 remainder in M5 is the
  `WorldCanvas`, spatial audio, the state machine.
- **Two items came from building, not the backlog:** M3-07a (typed native
  components from Dart, before physics) and M3-08b (ergonomics, mip
  chains, nested prefabs); M3-16c (the allocation gap) closed a status §3
  row. Recorded in the blueprint as 7a/8b and under item 16.

## 5. Known gaps carried forward

Owned by the milestone named; the status §3 table is the living copy.

- **E1 — Image-based lighting and light culling (the M3 stream, next).**
  Environment light is a constant ambient term, so metals read dark and
  every draw sees the 8 nearest lights to the camera. Next on this stream
  by the user's call: IBL first.
- **E2 — Published SDK artifacts (public readiness (b), C6).** `package:fynkel`
  and `package:fynkel_flutter` are path dependencies into the checkout;
  the hook lock is a different shape from the project lock; ADR-0005,
  `LICENSE`, `CONTRIBUTING.md`, CI on a fork, the ABI bump.
- **E3 — A physical iOS device and a second machine (M6).** Every number is
  from one M3 Max; the game ran on the simulator only.
- **E4 — Everything on the Flutter UI thread (M5, ADR-0007).** Step,
  extract and render on one thread; the stress scene's GPU frame beside
  Flutter's raster is the first place it shows.
- **E5 — Physics V1 limits (M5 as the reference game needs them).** One
  collider per entity, no joints, static mesh colliders only, the
  character neither pushes bodies nor rides platforms, collider outlines
  drawn by no host.
- **E6 — Audio V1 limits (M5).** 2D only, no effects or sends, no one-shot
  handle, one decoder per streamed voice; spatial audio is Tier 2.
- **E7 — Animation V1 limits (M5).** No state machine, timeline, 2D blend
  spaces, per-bone masks, IK, morph targets.
- **E8 — Input (after M3).** Apple-only gamepads and pointer capture, a
  fixed touch overlay, rebinding with no runtime API of its own.
- **E9 — Native components' Inspector hints in an editor table (M4/M3
  shared).** ADR-0018's `#[fynkel(...)]` attributes on the Rust structs are
  still to do; the editor reads a table for the 23 built-ins.
- From M2: **D8** cache hygiene (M6); the first real migration fixture
  pair is in (materials v1 → v2).

## 6. Decision

**GO.** M3 built the game it was asked to build, from code, with the
numbers recorded and the frame paths instrumented; the two exceptions are
decisions, not failures, and each has an owner (E2, E3). The M3 stream
continues on `main` with the renderer's E1 (IBL) while M4 (the editor)
proceeds on its branch; M5 opens when M4 closes.
