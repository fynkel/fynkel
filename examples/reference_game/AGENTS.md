# AGENTS.md — Fynkel Reference Game

Instructions for tools and AI agents working in this Fynkel project. Humans
are welcome too. Everything below is checkable by a machine: run the commands,
read the JSON, trust the exit codes.

## What this project is

A Flutter application whose 3D world is run by the Fynkel Engine: a Rust
runtime driven from Dart. Gameplay logic is Dart classes (`Behaviour`
subclasses); scenes, prefabs, materials and asset sidecars are strict JSON
documents validated against JSON Schemas. The project is a normal Dart
package: `flutter`, `dart` and `git` work as usual.

```text
fynkel.project.json     the project: startup scene, asset root, input actions, layers and tags, physics (gravity), quality, component registry, targets
fynkel.lock.json        runtime/tool/schema versions this project was created with (never edit by hand: `fynkel project lock`)
pubspec.yaml            Flutter app; depends on package:fynkel (SDK), package:fynkel_flutter (viewport + loop) and fynkel_generator (dev)
lib/main.dart           the app: loads the project, FynkelGameView (frame loop + 3D viewport) with the screens over it, chosen by GameState.screen: the title (lib/ui/menu.dart), the HUD (lib/ui/hud.dart), the pause menu, the settings panel (lib/ui/settings.dart: volumes, mute, quality, key rebinding), the results
lib/game/game.dart      Game.load(projectDir): one World, behaviours registered, the startup scene (the Menu) loaded; the flow — play() the Playground, finish() the Results, toMenu() — each a scenes.transition
lib/ui/*.dart           the screens: plain Flutter widgets bound to GameState (nothing reads the engine per frame)
lib/game/*.dart         the game's behaviours (@FynkelBehaviour classes): player.dart (walks/sprints/jumps the CharacterController in the camera's frame, drives the character's locomotion blend space from its speed, plays the jump and the wave layer, counts footstep markers and plays a footstep per marker, dies on `hazard` zones with the `hit` sound, restarts), collectible.dart (a coin, tagged `pickup`: scores when the object tagged `player` enters its `collect` zone, plays its `pickup`, spawns the burst prefab, destroys its instance), switch.dart + gate.dart (E on the pad opens the gate; the pad answers only the `player`-tagged object); game_state.dart holds the observable fields the HUD binds

lib/generated/          GENERATED by `fynkel codegen --project .` — never edit; commit

assets/materials/       *.material.json   PBR fields (base_color, metallic, roughness, <slot>_texture, …) for fynkel.pbr@1, or parameters/textures for a custom shader
assets/models/          glTF/GLB sources + <file>.meta.json sidecars (asset id, importer, sub-asset ids)
assets/textures/        PNG/JPEG sources + sidecars

```

## The loop: validate → codegen → build → test

After every change, in this order, all must exit 0:

```sh
fynkel validate --json                 # documents, sidecars, references, lock; exit 1 on errors
fynkel codegen --project . --check     # generated behaviour registration + schemas are current (exit 2 = stale: run without --check)
flutter analyze                        # Dart static analysis
flutter test                           # the game loads headlessly and behaviours run (cooks first via package:fynkel/testing.dart)
fynkel test --headless --json          # cooks, then the startup scene on the Rust headless host, N deterministic ticks
```

The runtime reads `.fynkel/cache` only — never a source document or model.
`fynkel run` validates, cooks and runs the app (`flutter run` with
`FYNKEL_PROJECT` pointing here; `-d <device>` for an iPhone); a plain
`flutter run` needs `fynkel cook` first, and a missing or stale cache is a
load error (`FYN-R0001`/`R0002`) naming the fix. Cooking also stages the
cache into `fynkel_cache/`, which the app bundles as Flutter assets and
unpacks at start-up when `FYNKEL_PROJECT` is not on the machine it runs on
(a device, a shipped build) — so cook before building for a device. `fynkel render --out out.png` cooks and draws the startup
scene without a window (needs a GPU; not for headless CI).

## Commands (all support `--json`; exit 0 ok, 1 errors, 2 usage/unopenable)

```sh
fynkel validate [--project <dir>]                       whole project
fynkel project describe                                 the project file, resolved
fynkel project lock [--check]                           write / compare fynkel.lock.json for the installed tools
fynkel schema list | describe <type|kind>               every component type / document kind this build knows
fynkel scene inspect|validate <path> [--expand]         one scene; --expand shows prefab instances expanded
fynkel scene apply <path> --patch <ops.json> [--dry-run] one authoring transaction (commands below)
fynkel prefab inspect|validate|apply ...                 same for prefabs
fynkel material inspect|validate <path>                  a material against its shader manifest
fynkel document new <kind> <name> [--out <path>]         a fresh, valid, empty document (scene, prefab, material, ...)
fynkel document format <path>... [--check]               canonical formatting
fynkel asset list | resolve <uuid>[#sub] | init <file>   the asset database (ids come from sidecars and documents)
fynkel import <file>...                                  (re)import sources; fills sidecar sub-asset ids
fynkel cook [--force] [--prune]                          cook the project's assets into .fynkel/cache (scenes expanded, prefabs applied) and stage them into fynkel_cache/ for the app bundle
fynkel codegen --project . [--check]                     behaviour registration + schemas from @FynkelBehaviour classes
fynkel test --headless [--scene <path|id>] [--steps N] [--input <file.input.json>]   cook, then the Rust headless host over the startup scene (or --scene); --input replays a recording against the actions
fynkel state dump [--scene <path|id>] [--steps N]        cook, then the world state after N ticks, keyed by authoring id
fynkel render [--scene <path|id>] [--out <png>] [--size WxH] [--quality <profile>]  cook, then an offscreen render of the scene
fynkel run [--no-cook] [-d <device>] [-- <flutter run args>]   validate, cook + stage, then `flutter run` with FYNKEL_PROJECT set (a device loads the bundled cache)
fynkel migrate <path|dir> [--dry-run]                    bring documents to the current formatVersion
```

Every diagnostic is one record: `{ code, severity, message, document?,
pointer?, line?, column?, suggestion?, related? }`. Codes are stable and
namespaced: `FYN-D` documents, `FYN-A` assets, `FYN-P` project, `FYN-E`
editing, `FYN-B` behaviours at load, `FYN-G` codegen. `pointer` is an RFC 6901
JSON pointer into `document`. Fix errors at the pointer; warnings do not fail
a command.

## Scenes

A scene is `{ "$schema", "formatVersion", "id", "name", "entities": { <uuid>:
entity } }`. An entity is `{ "name", "parent": <uuid>|null, "children":
[<uuid>], "components": { <uuid>: { "type", "version", "data" } } }`. Every
id is a lower-case UUID and is permanent: never renumber, never reuse. New
ids: `uuidgen | tr A-Z a-z`, or let `fynkel document new` / `fynkel scene
apply` mint them.

Component types:

- `fynkel.Transform` — position `[x,y,z]`, rotation quaternion `[x,y,z,w]`, scale. Every drawn entity has one.
- `fynkel.MeshRenderer` — `mesh: { asset, sub: "mesh/<name>" }`, `material: { asset }`, `cast_shadows`, `receive_shadows` (the first `DirectionalLight` with `cast_shadows` casts one PCF shadow map), `visible`.
- `fynkel.Camera` — `projection`, `fov_y` (radians), `ortho_height`, `near`, `far`, `priority`, `exposure_mode` (`auto` meters the sun; `manual` uses `exposure`, EV100).
- `fynkel.DirectionalLight` (`intensity` in lux), `fynkel.PointLight` / `fynkel.SpotLight` (`intensity` in candela, `range` in metres; spot `inner_angle` / `outer_angle` in radians) — `color` is linear RGB.
- `fynkel.Environment` — `ambient_color` × `ambient_intensity` (lux), optional equirectangular `sky` texture with `sky_intensity` (nits) and `sky_rotation`. At most one per scene; without it the defaults apply.
- `fynkel.Volume` — the frame's *look* by where the camera is (R3a): `profile` names a `<name>.volume.json` (`fynkel document new volume <name>`; blocks `ambientOcclusion { radius, intensity }` (R3a) and `bloom { intensity, threshold, scatter, tint }` (R3b; off until a volume gives it an intensity), every field optional — present overrides, absent inherits), `shape` `global` | `box` (`size`) | `sphere` (`radius`), `blend_distance` (metres of fade outside the shape), `weight` 0…1, `priority` (higher wins). A volume shapes what the quality profile has on; it never turns on what the profile has off.
- `fynkel.RigidBody` — `body_type` `static` | `dynamic` | `kinematic`, `mass` (kg, dynamic), `linear_damping`, `angular_damping`, `gravity_scale`, `ccd`. Physics owns a dynamic body's transform; a kinematic one follows the transform your behaviour writes (the Gate's slab is static geometry moved the same way) and pushes dynamic bodies.
- `fynkel.Collider` — `shape` `box` (`size` = half extents) | `sphere` (`size[0]` = radius) | `capsule` | `mesh` (`mesh` sub-asset, static only), `offset`, `friction`, `restitution`, `is_sensor` (trigger events, no forces), `mask` (the layers it collides with: bits of the project's `layers`; the collider's own layer is its object's `fynkel.Layer`). Alone it is static geometry (the starter's Floor); with a `RigidBody` it is that body's shape. Scaled by the entity's scale.
- `fynkel.CharacterController` — a kinematic capsule walked by gameplay (no `RigidBody`/`Collider` next to it: `FYN-H0006`): `radius`, `height`, `center` (the origin is at the feet by default), `skin_width`, `max_slope` (radians; steeper slides), `max_step_height`, `snap_to_ground`, `gravity_scale`, `mass` (what it pushes dynamic bodies with), `speed`, `jump_speed`, `turn_speed` (faces its motion), `move_action`/`jump_action` (named: the runtime walks it from those actions in the frame of the `ThirdPersonCamera` that targets it, jumping on the press while grounded; empty: your behaviour sends `move(v)`/`jump()`), `mask` (its layer is its object's).
- `fynkel.ThirdPersonCamera` — on the camera entity: `target` (the followed entity's name), `pivot` (offset from the target's origin), `distance`, `min_distance`, `yaw`/`pitch` (radians, written back each tick), `min_pitch`/`max_pitch`, `look_action` (axis2d turning it at `sensitivity` rad/s per unit), `collision_radius` (a sphere cast from the pivot pulls the camera in before walls; 0 disables), `mask`. Placed after the tick's transforms; its own `Transform` is overwritten.
- `fynkel.Rotator` / `fynkel.Oscillate` / `fynkel.Follow` / `fynkel.LookAtCamera` / `fynkel.LifetimeDespawn` / `fynkel.Emitter` — the native catalogue (below): motion, following, billboards, timed despawn and spawning at a rate with no Dart code.
- `fynkel.Animator` — `clip: { asset, sub: "anim/<name>" }` (or `{ asset: <blend document> }`), `speed`, `looping`, `playing`, `weight`, `additive`, `root_motion`: plays the clip (or blend space) over the named entities under this one; on a descendant of another animator it is a layer (see "Animation"). `fynkel.Skin` — next to a skinned `MeshRenderer`: `skin: { asset, sub: "skin/<name>" }`, `skeleton` (the name of the joint root entity, found under the tree's root; empty: the root itself).
- `game.*` — this project's behaviours (Dart classes in `lib/game/`); `data` holds the `@Expose` fields, validated by `schemas/behaviours/<id>.schema.json`.

Exact fields and defaults: `fynkel schema describe fynkel.Camera --json` for
native types, `schemas/behaviours/*.schema.json` for behaviours.

Materials (`assets/materials/*.material.json`, `fynkel.pbr@1`): `alpha_mode`
`opaque` | `mask` (+ `alpha_cutoff`) | `blend` (drawn after the opaque
scene, sorted back-to-front, casts no shadow), `double_sided`.

Quality (`fynkel.project.json` `quality.profiles`, `default`): `shadows`,
`shadowResolution`, `ambientOcclusion`, `bloom`, `msaa` (1 or 4 in V1),
`renderScale`, `anisotropy` — what the device can afford; how it looks
is the scene's `fynkel.Volume`s.
The renderer runs the default profile; switch at runtime with
`FynkelViewportController.quality = '<name>'` (the starter's HUD cycles
them on Q) or render one with `fynkel render --quality <name>`.

Asset references are `{ "asset": "<uuid>", "sub": "<sub-asset id>"? }`. The
uuid is the `id` in the source's `.meta.json` sidecar or the document's
envelope, never a path. Find one: `fynkel asset list --json`.

### Editing scenes with commands

Prefer `fynkel scene apply <scene> --patch ops.json` over hand-editing: it is
transactional (all or nothing), validates the result, and `--dry-run` prints
the diff. A patch is a JSON array of commands, e.g.

```json
[
  { "command": "createObject", "name": "Player", "parent": null,
    "components": [ { "type": "fynkel.Transform", "version": 1,
      "data": { "position": [0, 0, 0], "rotation": [0, 0, 0, 1], "scale": [1, 1, 1] } } ] },
  { "command": "setField", "entity": "<uuid>", "component": "<uuid>", "field": "speed", "value": 2.0 }
]
```

Commands: createObject, deleteObject, renameObject, reparentObject,
addComponent (`entity`, `component: { type, version?, data? }`),
removeComponent, moveComponent, setField, unsetField, assignAsset,
instantiatePrefab,
setPrefabOverride, revertPrefabOverride, unpackPrefab, createMaterial,
saveDocument. Omitted ids are minted; `--json` prints the affected ids and the
new revision. `unpackPrefab` replaces an instance by its expansion in place and
so reads the prefabs the way `inspect --expand` does — `--prefabs <dir>`, else
the document's directory. Hand edits are fine too — run `fynkel validate`
afterwards.

## Behaviours (gameplay code)

```dart
@FynkelBehaviour(id: 'game.PlayerController')   // stable, namespaced id; `fynkel.` is reserved
class PlayerController extends Behaviour {
  @Expose(min: 0, tooltip: 'Metres per second') double speed = 4.0;   // authored data
  @Expose() Vec3 spawn = Vec3.zero;
  @Expose() AssetRef? projectile;                                      // an asset reference

  @override
  void fixedUpdate(FixedUpdateContext context) {                       // deterministic, per tick
    transform.position = transform.position + Vec3(speed * context.dt, 0, 0);
  }
}
```

- Lifecycle: `onCreate → onEnable → start → fixedUpdate / afterPhysics / update / lateUpdate → onDisable → onDestroy`. Simulation goes in `fixedUpdate` (fixed `context.dt`); presentation-only work in `update`.
- Exposed field types: `double`, `int`, `bool`, `String`, `Vec3`, `Quat`, `AssetRef`, each optionally nullable; literal initializers become defaults.
- After adding/changing a behaviour class or an `@Expose` field: `fynkel codegen --project .`, then commit `lib/generated/` and `schemas/behaviours/`. Register a new type in `fynkel.project.json` → `components` too (`"game.X": { "kind": "behaviour", "version": 1 }`).
- A scene component of a type that is not registered at runtime loads with warning `FYN-B0001`; data a field rejects is `FYN-B0002`. Neither stops the scene.

## Native components from a behaviour

A behaviour reaches every native component on its object — the same
classes the scene authors, as immutable values with `copyWith`:

```dart
final mesh = get<MeshRenderer>()!;                 // null when the object has none
set(mesh.copyWith(visible: false));                // a command at the next tick; reads back now
if (!has<PointLight>()) set(const PointLight(color: Vec3(1, .5, .2), intensity: 800, range: 12));
remove<SpotLight>();                               // Transform and Name cannot be removed
world.spawn(name: 'Twin', transform: t)..add(mesh)..add(light);   // lands in the spawn's tick
```

- `get`/`has`/`set`/`remove` on `Behaviour` forward to `gameObject`; on any
  `GameObject` there is also `add` (= `set`), `setPresentation` (the
  presentation lane: applies at once, for `lateUpdate`) and `components`.
- Reads are the value the last tick left (one query per object per tick)
  merged with what you set this tick. A value the world rejects (a negative
  light range) is a diagnostic on the next tick and the read falls back.
- Not for a loop over thousands of objects every tick; a behaviour on its
  own object is the intended use.

## Physics (Rapier, native; the Dart side sends commands and reads state)

`fynkel.project.json` → `physics`: `gravity` `[x,y,z]`. The project's
top-level `layers` (up to 32 names, `default` first) and `tags` (up to 32)
belong to every object: an object's layer is its `fynkel.Layer` (absent =
`default`), and its colliders collide as that layer;
`world.layerMask(['props'])` turns names into a collider's `mask` or a
raycast's. Bodies and colliders are components (above); a
behaviour on a dynamic body drives it with forces, never by writing its
transform (a simulation-lane transform write is a teleport, a presentation
write is rejected `FYN-…physics_owned`):

```dart
applyImpulse(const Vec3(0, 5, 0));                 // also applyForce, applyTorque, setLinearVelocity, …
gameObject.setKinematicTarget(p, q);                // kinematic bodies; teleport(p) for any body
final v = bodyState()?.linearVelocity;             // one query; null without a RigidBody

@override
void onCollisionEnter(Contact c) {                  // also Stay/Exit, onTriggerEnter/Exit
  final other = world.byEntity(c.other(gameObject.entity));
  if (c.impulse > 10) crack(c.point, c.normalFor(gameObject.entity));
}

final hit = world.raycast(origin, direction, maxDistance: 20, mask: world.layerMask(['default']));
world.overlap(ColliderShape.sphere, const Vec3(2, 0, 0), centre);   // also shapeCast, raycastAll
```

Contact callbacks run right after each tick's step on the behaviours of
both objects; `Contact` carries `point`, `normal` (a → b) and `impulse`
(0 for triggers and exits). `fynkel validate` checks values (`FYN-H0001`/
`H0002`, `H0005`/`H0007` for the character and camera rig), a mesh collider
on a moving body (`H0003`), a dynamic body without a collider (`H0004`,
warning) and a body or collider next to a `CharacterController` (`H0006`).
`fynkel test --headless` prints the run's bodies, colliders, characters
and contact counts; the simulation is deterministic per platform (same
scene, same commands → same checksum).

Characters (`fynkel.CharacterController`, above): with `move_action`/
`jump_action` set the runtime walks the capsule itself — WASD/stick
relative to the `fynkel.ThirdPersonCamera` whose `target` is the entity's
name, jump on the press while grounded — and a behaviour only reads:

```dart
final s = characterState();                        // null without a controller
if (s != null && s.grounded && Input.pressed('jump')) jump();   // your own rules: leave the actions empty and drive it
move((right * stick.x + forward * stick.y) * speed);            // metres per second, this tick only; none = standing still
```

The pattern with sprint and a double jump is
`packages/fynkel/example/player_controller.dart`.

## Animation (clips over named entities; a skinned character; blend spaces, layers, markers)

`fynkel import` keeps a glTF's animations (`anim/<name>`, with the markers
authored in an animation's `extras.markers`), skins (`skin/<name>`) and
skinned meshes (`JOINTS_0`/`WEIGHTS_0`). A clip keys *named nodes* under
the entity that carries the `fynkel.Animator` — a bone, a door and a
lamp are the same thing to it — so the skeleton is ordinary entities:
`tools/playground.py` authors the player's joints (`hips` → `spine` →
`head`, the arms and the legs, from `tools/character.py`'s `SKELETON`) as
children of the Player in their bind pose, the skinned `Body` next to
them with a `fynkel.Skin { skin, skeleton: "hips" }`, and the `Visor`
under `head`. The clips are authored in place (no root motion): the
`CharacterController` moves the entity, the animator only poses the
joints.

The Player's animator plays a **blend space** (M3-19c),
`assets/models/player.blend.json` — `{ parameter: "speed", points:
[idle@0, walk@4, run@7], sync: "phase" }`, written by
`tools/playground.py`: an `Animator.clip` naming the document mixes the
two points around the parameter, phase-synced (the feet agree between
the walk and the run; `state.duration` is the blended lap). `game.Player`
sets `speed` every tick from the controller's planar velocity
(`animation.setParameter('speed', v)`), so the stride follows the speed
with no clip switching; the jump is a one-shot played over it
(`jumpClip`, told by the scene) and the landing crossfades back to the
space. A **layer** is a second animator on a descendant: the `spine`
joint carries the wave layer — the character's `wave` clip (`anim/wave`,
keying the right arm alone), `additive: true`, paused on its first frame
until `game.Player` plays it once on the `wave` action (F). **Markers**:
the walk and the run carry `step_l`/`step_r` (character.py writes them
into the glTF; a rig document authors them under `markers`), delivered
to the Player's `onAnimationMarker` from whichever clip dominates the
blend, counted into `GameState.footsteps` for the HUD.

`tools/playground.py --hero <name>.rig.json` (M3-19b, opt-in, never
committed) dresses the Player in a downloaded character instead:
`fynkel import Idle.fbx Walking.fbx "Fast Run.fbx" Jumping.fbx --rig
hero` writes the rig document (the first file is the skeleton, every
file's clip is matched to it by bone name — rename the clips to `idle`,
`walk`, `run`, `jump`; add `markers` for footsteps; a `wave` clip is
optional and gives the layer, on the `Rig`), then a `Rig` child
instances `{ asset: <rig>, sub: "prefab" }` (turned to face -Z), the
blend space's points are the rig's `anim/idle` … (`--hero <file.glb>`,
M3-19a, still takes one glTF whose clips are named `idle`, `walk`, `run`,
`jump` and, optionally, `wave`); `test/game_test.dart`'s posed test is
rig-agnostic (it reads the jump clip and the wave layer off the Player
and watches every joint under it). A behaviour drives it:

```dart
animation.setParameter('speed', v);                // the blend space reads it every tick (clamped to its points)
animation.play(jump, looping: false);              // a one-shot over it; crossfade(locomotion, 0.15) blends back
animation.crossfade(walk, 0.15);                   // a timed blend between plain clips
animation.speed = 1.5; animation.pause(); animation.resume(); animation.stop();   // stop rewinds and holds
animation.weight = 0.5;                            // a layer's weight (0…1)
final s = animation.state;                         // clip, time, duration, parameter, weight, playing, isFading, rootDelta

@override
void onAnimationEnded(AnimationEnded e) { … }      // a one-shot passed its end (held on its last frame)
@override
void onAnimationMarker(AnimationMarker e) { … }    // e.name, e.clip — a marker crossed (loops and backwards included)

final spine = gameObject.findDescendant('spine')!;                   // a joint is an entity: read or override it
spine.animation.play(spine.get<Animator>()!.clip, looping: false);   // the layer on it plays like any animator
```

Clip references are `AssetRef(characterAsset, sub: 'anim/<name>')`; a
blend space is `AssetRef(blendDocumentId)`. A clip or space the scene
did not name is loaded from the cache when first played (a space brings
its points' clips); one the cache lacks is `clip_unavailable` once and
the animator waits. `fynkel validate` checks a blend document
(`FYN-D0600` points not strictly increasing, `FYN-D0601` a point's clip
is not a clip of a rig or model). `fynkel test --headless` prints the
run's animators, clips (a space counts once), skins, skinned meshes and
markers; `fynkel render --steps <n>` draws the pose after `n` ticks.

## The native catalogue (movement without a behaviour)

Six components the runtime ticks itself, in Rust, before physics — a
scene with 5 000 of them costs microseconds per tick where 5 000 Dart
`fixedUpdate`s would not. Author them in the scene (or `add` them from a
behaviour like any native component); nothing to write or register.

- `fynkel.Rotator` — turns the local rotation `speed` rad/s about `axis` in `space` `local` (the entity's own axes) or `world`.
- `fynkel.Oscillate` — moves along `axis` by `amplitude · sin(2π · frequency · t + phase)`; it adds the *change* in offset each tick, so a transform you write from gameplay shifts the rest position instead of fighting the motion.
- `fynkel.Follow` — places the entity at the world position of the entity named `target` plus `offset` (snapped when `smoothing` is 0, else eased at `smoothing`/s); `look_at` turns its −Z at the target. Runs after physics on the tick's final poses, like the camera rig.
- `fynkel.LookAtCamera` — turns the entity's +Z at the active camera (highest `priority`); `lock_y` keeps it upright (a billboard). After physics.
- `fynkel.LifetimeDespawn` — destroys the entity and its subtree `seconds` after the component appeared (`onDestroy` runs as for `destroy()`).
- `fynkel.Emitter` — instantiates `prefab` `rate` times per second at the emitter's world pose (unparented, an anchor named after the prefab), each with a `LifetimeDespawn` of `lifetime` (0 keeps them) and its dynamic bodies launched at `velocity`; `max_alive` caps the live ones (0 = unlimited); `enabled` pauses it. A prefab the scene does not reference loads nothing and reports `prefab_unavailable` once.

Values the runtime would reject are `FYN-H0008` at `fynkel validate`
(a zero axis, a negative amplitude/rate/lifetime/smoothing/seconds).
`World.systemTimes()` (the starter's HUD `systems` line, `fynkel test
--headless`'s `systems:` line) shows what each of these cost last tick.

## Finding objects, spawning, prefabs

```dart
final player = world.find('Player');                // by name, as the last tick left it
final hand = player?.findChild('Arm/Hand');         // a path of direct children; findDescendant(name) searches deep
for (final coin in world.findAll('Coin')) { … }     // every entity with that name
final coin = world.findWithTag('pickup');           // by a project tag; findAllWithTag for every one
final box = world.spawn(name: 'Box', transform: t, parent: player)
  ..add(const RigidBody(bodyType: BodyType.dynamic, mass: 2, …))
  ..add(const Collider(shape: ColliderShape.box, size: Vec3.one, …))
  ..applyImpulse(const Vec3(0, 4, 0));               // all in the spawn's tick
final turret = world.instantiate(turretPrefab, transform: t, name: 'Turret');
turret.findChild('Barrel');                          // the prefab's entities are its children
```

- `find`/`findAll`/`findChild`/`findDescendant`/`findWithTag`/
  `findAllWithTag` read one entity table per tick; a rename, reparent or
  tag change staged this tick shows up next tick.
- Tags and the layer speak the project's names (`tags`, `layers` in
  `fynkel.project.json`): `go.tags` (a copy), `go.hasTag('pickup')`,
  `go.addTag('pickup')`, `go.removeTag('pickup')`, `go.layer` (`default`
  without a `fynkel.Layer`) and `go.layer = 'props'` — writes for the next
  tick, readable now; the colliders regroup in that tick. A name the
  project does not declare throws, listing the ones it does.
- A freshly spawned object can be configured — components, transform,
  parent, body commands, children — in the same `fixedUpdate`; everything
  lands in the spawn's tick.
- `instantiate(prefab)` takes the prefab's asset id (`AssetRef` or UUID
  text) from the cooked cache and returns the anchor object immediately;
  `world.lastInstantiate` is the report, a bad id throws
  `FynkelInstantiateError`. Prefabs may nest; a cycle is `FYN-D0402`.
- Name assets through the generated `Assets` class
  (`lib/generated/assets.g.dart`, written by `fynkel codegen` and by the
  editor when assets change): `world.instantiate(Assets.prefabs.coin)`,
  `scenes.transition(Assets.scenes.main)`, `Assets.models.cube.meshes.cube`.
  They hold ids, never paths; they are getters, so `final`, not `const`.
  A path known only at runtime: `world.assets.find('prefabs/coin')`.
- Build objects from code with `world.build(ObjectSpec('Crate',
  components: const [RigidBody(), Collider()], behaviours: [Spinner()],
  children: [...]))`; a function returning an `ObjectSpec` is a code
  prefab (call it per copy — behaviour instances attach once).
  `ObjectSpec.prefab(Assets.prefabs.coin, tags: ['pickup'])` places a
  prefab asset with overrides on its root.
- `world.createPrimitive(Primitive.cube)` (or `ObjectSpec.primitive`) makes
  a built-in shape with its collider; `world.createMaterial(PbrMaterial(
  baseColor: …))` returns an `AssetRef` for a `MeshRenderer`;
  `obj.clone()` copies a spawned object and its subtree, scripts and all
  (Unity's `Instantiate(obj)`).
- Animate a value with a tween, not a hand-written coroutine:
  `yield transform.moveTo(target, 0.5, ease: Ease.outCubic)` in a
  coroutine, `rotateTo`, `scaleTo`, or `tween(0.0, 8.0, 0.3, (v) => …)`.
- To make a level or prefab file from code, write the same `ObjectSpec`s
  with `package:fynkel/authoring.dart` from a tool script:
  `ProjectWriter('.', registerBehaviours: registerBehaviours)
  .writeScene('scenes/level', SceneSpec('Level', specs))`. Run it again
  after a change; ids stay stable and editor additions are kept.

## Audio (cooked clips, a streamed track, three buses, a voice limit; docs/audio.md)

`assets/audio/*.ogg` are imported by the cook like models (`fynkel.audio`
v2, a sidecar with the asset id) and decoded to PCM in the cache — or,
with `"settings": { "stream": true }` in the sidecar (`music.ogg`),
cooked as a `STRM` chunk of the source bytes that the runtime decodes on
its own thread as it plays, a second ahead of the mixer (a long track
without 25 MB of PCM in memory; `stats.starved` counts the callbacks the
decoder fell behind in — 0 on a healthy machine). A `fynkel.AudioSource`
names a clip (`clip`), a bus (`master`, `music`, `sfx`), `volume`,
`pitch`, `looping`, `playing` and `priority`; the one
`fynkel.AudioListener` (on the Camera) scales everything. The `Music`
entity's source loops on the music bus from the load, on the Rust host
too. The mixer runs on the audio thread with 32 voices: a new sound past
the limit steals the lowest-priority voice or is refused (`fynkel test
--headless` prints `1 sources, 1 sounds (1 streamed), … started / stolen
/ refused`). From a behaviour:

```dart
world.audio.play(stepLeft, volume: 0.6, pitch: 1.05);   // a one-shot by asset id: no component, no event (Player, Collectible)
audio.play(); audio.stop(); audio.volume = 0.5;          // an object's own source (the Music entity's, say)
final s = world.audio.stats;                             // voices, started, ended, streams, starved, device
world.audio.setBus(AudioBus.music, 0.5);                 // the settings store applies its volumes here
```

`game.Player` exposes `stepLeft`, `stepRight`, `hit` and `stepVolume`,
`game.Collectible` exposes `pickup` (all `AssetRef`s the scene sets from
the sidecars; `AssetRef.none` is silent). A one-shot's clip registers
the first time it is played; a clip the cache cannot read is
`sound_unavailable`. `lib/main.dart` passes `audio: true` to the view,
which opens the output device, suspends it while the app is hidden and
closes it on dispose; `flutter test` runs on the null backend (the clock
runs, the voices count, nothing is heard). Adding a sound: drop the file
in `assets/audio/`, `fynkel import assets/audio/<file>.ogg` (writes the
sidecar; add `stream: true` for music), reference its id, `fynkel cook`.

## Scenes at runtime, zones, settings

```dart
world.scenes.transition(resultsSceneId);            // from any callback: loads at the start of the next frame
await world.scenes.transition(levelTwo);            // the LoadReport, or a FynkelLoadError
world.loadScene(hudScene, mode: LoadMode.additive); // now, on top of what is loaded (not from a callback)
world.unloadScene(hudScene);                        // only that scene's entities; runtime spawns stay
world.loadedScenes; world.scenes.current; world.scenes.state; // empty | pending | ready | failed
```

- `loadScene(id)` (the default `LoadMode.replace`) unloads **everything**
  first — every loaded scene, every `spawn`/`instantiate` — so nothing
  survives a level change; `additive` keeps the world and refuses an id
  that is loaded already (`FYN-R0011`). Handles of destroyed objects go
  dead on the next frame; a behaviour on one gets `onDestroy`.
- `fynkel.TriggerZone { event, once }` next to a sensor `fynkel.Collider`
  (`is_sensor: true`, else `FYN-H0009`) turns enter/exit into a named
  event: `Behaviour.onZoneEnter(e)`/`onZoneExit(e)` on the zone's and the
  visitor's behaviours, `world.zones.on('collect', (e) { … })` anywhere;
  `e.zone`, `e.other`, `e.event`. `once: true` fires one enter and
  removes the zone (a pickup).
- The flow (M3-15): the Menu is the startup scene; `Game.play()` resets
  `GameState` and transitions to the Playground; `winDelay` (1.5 s) after
  the last coin `Player` calls `finishRun` (`GameState.finish()` snapshots
  the run into `lastRun`, then the Results scene, whose `Jingle`
  `AudioSource` plays the win sting from its load); `Game.toMenu()`.
  `GameState.screen` follows `scenes.current` through a listener in
  `Game` — the overlay switches on it. The three scenes are ordinary
  replace loads: the level's entities and behaviours are gone in the
  Menu and the Results (the menus carry no behaviours at all).
- Settings: `settings.json` under the platform's application-support
  directory (`SettingsStore.defaultPath('Fynkel Reference Game')`, wired in
  `Game.load(settingsPath:)`): `master_volume`, `music_volume`,
  `sfx_volume`, `muted`, `quality`, `input.rebinds` (`action →
  [bindings]`, the input grammar below, laid over the project's actions
  at once and after every load). `game.settings.current`,
  `game.settings.update(doc)` / `edit((s) => s.rebind('jump',
  ['keyboard:J']))` write the file immediately; a missing file is the
  defaults, an invalid one is reported and ignored. The settings panel
  (lib/ui/settings.dart, from the title and the pause menu) is the
  worked example: sliders and the mute switch call `update(copyWith(…))`,
  the quality goes to the viewport controller too, a rebind takes the
  next key through the view's `onKeyEvent` (`FynkelInputCapture.keyName`)
  and keeps the project's other devices (`current.rebind(action,
  ['keyboard:<key>', …gamepad/touch])`; `Game.bindingsOf(action)` reads
  what is in force); the panel rebuilds from `settings.addListener`. Q
  writes `quality` too.

## Input (actions, never keys)

`fynkel.project.json` → `inputActions` declares every action a behaviour
can read: `"<name>": { "type": button | axis1d | axis2d, "bindings":
["<device>:<control>", …] }`. Bindings: `keyboard:<Key>` (`A`…`Z`,
`Space`, `ArrowUp`, `ShiftLeft`, `F1`, …), `keyboard:WASD` / `Arrows` /
`<l>/<r>/<d>/<u>` for `axis2d`, `keyboard:<neg>/<pos>` for `axis1d`;
`mouse:left|right|middle|back|forward`, `mouse:wheel`, `mouse:delta`;
`gamepad:south|east|west|north|leftShoulder|…|menu|options|home`,
`gamepad:leftTrigger|leftStickX|…`, `gamepad:leftStick|rightStick|dpad`
(an axis control takes a scale — `mouse:delta*0.0025` turns pixels into
stick units);
`touch:overlay/<name>` (a stick or button the app's `TouchOverlay` draws on
phones). `fynkel validate` rejects a binding the runtime cannot compile
(`FYN-P0009`).

```dart
final move = Input.action2D('move');   // Vec2 in the unit square, every tick while held
if (Input.pressed('jump')) jump();      // exactly one tick per press, whatever the frame's tick count
if (Input.held('run')) speed = 2;
```

`pressed`/`released` are edges (button actions only); `held`/`axis`/
`action2D` are state. Read them in `fixedUpdate`; `update` sees the
frame's raw edges. A relative control (`mouse:delta`) is motion consumed by
one tick as a rate (`look · dt` is the motion); bind it with a scale
(`mouse:delta*0.0025`) so pixels read like a stick. Tests:
`test/collect_all.input.json` (tools/route.py) is a recording (`{ "fynkel":
"input-recording", "formatVersion": 1, "frames": [{ "dt", "events": [{
"device", "control", "phase": down|up|axis|move|reset, "x", "y" }] }] }`);
`loadInputRecording(path).replay(world)` runs it in `flutter test`,
`fynkel test --headless --input <file>` on the Rust host (per action: ticks
pressed/released/held). Without a world: `TestGameContext(input:
TestInput(actions: [('jump', ActionKind.button)]))`.

## HUD models and world labels (screens never read the engine snapshot)

`lib/game/game_state.dart` is a `GameModel`: one `ModelValue<T>` per fact a
screen shows (`late final collected = field(ModelValue(0));`), installed by
`Game.load` (`world.context.install(GameState())`, read back with
`game.state` / `world.context.service<GameState>()`). Behaviours write the
fields from their callbacks (`Collectible` counts, `Player` the clock and
deaths, `Switch` the hint); the app writes app facts (`state.paused`). A
field notifies on `!=` only, so a bound widget rebuilds when the game
changed what it shows and never per frame. Bind in Flutter
(package:fynkel_flutter): `ModelBinding<GameState>(model: game.state,
child: …)` hands the model down, `ModelBuilder<int>(value:
state.collected, builder: (_, n, _) => Text('$n'))` rebuilds one
widget, `state.collected.listenable` is a `ValueListenable` for
`ValueListenableBuilder`. Menu / HUD / pause / settings / results: a model
field (`screen`, `paused`, `lastRun`) the widget tree switches on —
lib/main.dart's `ModelBuilder<Screen>` picks `MenuScreen`, the HUD stack
or `ResultsScreen` (lib/ui) — with the game's own state left in the world
(`setPaused` on the view stops the loop while the pause menu is up;
`SceneManager.transition` changes scenes). The overlay sits in an
`ExcludeFocus`, so its buttons never take the keyboard from the viewport
and Escape / F1 / Q / a rebind's key keep reaching `onKeyEvent`.

Labels in the 3D scene: `ProjectionLayer(world: game.world, children:
[WorldLabel(target: coin, offset: Vec3(0, 0.9, 0), text: 'Coin'),
ProjectedAnchor(target: pad, offset: Vec3(0, 1.2, 0), child: SwitchPrompt())])`
in the view's `overlay` — the layer sizes the world's projection view from
its own layout, `FynkelGameView` projects every anchor once per frame
(`world.projection.update()`) with the frame's camera and interpolated
poses, and the layer moves its children with paint transforms (no
rebuilds). A child whose point is off screen, behind the camera or on a
dead object is not painted (`clampToEdges: true` keeps an in-front marker
on the edge). Occlusion is opt-in: `occlusionMask: world.layerMask(['walls'])`
hides the child when a collider on those layers sits between the camera
and the point; without a mask a label is never hidden by geometry. At most
64 anchors project per frame (blueprint §10); beyond that the newest are
dropped and `FYN-R0012` (`tooManyAnchors`, informational) is reported
once. In a test: `world.projection.add(object, offset:)`, `setViewport(w,
h)`, `update()`, then `anchor.x`/`y`/`visible`/`occluded`/`depth`.

## Do

- Run the loop above before declaring work done; paste the failing command's output when it fails.
- Keep ids stable; add new entities/components with fresh UUIDs.
- Keep documents canonical (`fynkel document format`) so diffs stay small.
- Put runtime-only state in plain fields; expose only what a scene should author.
- Commit generated files together with the source change that produced them.

## Don't

- Don't edit `lib/generated/`, `schemas/behaviours/` or `fynkel.lock.json` by hand.
- Don't put paths in asset references, or invent ids that are not in `fynkel asset list`.
- Don't rename component `type` ids or behaviour ids once scenes use them (add a new type and migrate).
- Don't call engine APIs from outside a behaviour callback or the host loop (`Time.*` and `Diagnostics.*` need a current GameContext).
- Don't commit or hand-edit `.fynkel/cache` or `fynkel_cache/`: they are derived, ignored by git, and `fynkel cook` rebuilds them. Don't read source documents at runtime either — the game loads from the cache by asset id.
