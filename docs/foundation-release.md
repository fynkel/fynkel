# Reproducing foundation qualification

Use the repository's pinned Rust toolchain and Flutter/Dart installation. Put
Flutter's bin directory first on PATH. Run on an otherwise idle Mac; stop game
windows and other builds before timing. The runner sets FYNKEL_CLI to the local
release binary and runs commands sequentially. Do not edit source during capture.

```sh
python3 -m unittest discover -s tools/tests
python3 tools/foundation_release.py --suite all
```

Each run creates a fresh directory in `target/foundation-release/` with exact
commands, tool versions, source hashes, exit status, durations, raw logs and
measurements. It retains failed commands and continues collecting other checks.
A zero exit means the selected checks passed, not that all platforms are certified.
Run `correctness` first if selecting individual suites: it rebuilds the CLI and
native libraries. `editor-history` needs the project generated by `editor-scale`.

Suites: correctness; native-scale; dart-scale (JIT and VM allocation counters);
dart-aot (compiled native-assets bundle); render (extraction, lights, animated
bounds); transparency (cold uploads and overlapping transparent objects);
editor-scale (10,001 assets, 40 measured sessions/cooks); editor-history
(inspector, apply/undo/redo); lifecycle (50 scene load/unload cycles and 10 worlds);
packages (both path and local Git package/editor consumption).

The reference machine regression alarm is checked in at
`benchmarks/foundation/budgets/mac-m3max-native.json`:

```sh
python3 tools/foundation_release.py --suite native-scale \
  --baseline benchmarks/foundation/budgets/mac-m3max-native.json
```

It requires matching machine/suite, complete workload keys, and p99 no worse
than the greater of 1.5× baseline or baseline + 100 μs. The absolute allowance
keeps sub-microsecond probes from becoming scheduler-noise gates. Structural
correctness and sparse-work candidate counts have their separate permanent tests.
This is a reproducible regression ceiling, not an end-to-end frame-rate promise.
A different machine requires a reviewed baseline; do not overwrite the reference
just to make a slow run pass. CI runs the native gate and preserves artifacts.

For platform qualification, create a fresh project, validate/cook it and run its
codegen check, analysis and tests. Build `flutter build macos --release` and
`flutter build ios --release` from that project. Verify bundled assets without a
source-project path, input, pause/resume, resize/orientation, background/foreground
and relaunch on actual hardware. Record the bundle hash, device, actions and
observations. A compile-only result, simulator or repeated run on the same Mac
cannot replace physical-iOS or second-Mac execution evidence.

The API source migration is intentional: replace `package:fynkel/fynkel.dart`
with `package:fynkel/gameplay.dart`, or `package:fynkel/advanced.dart` for native
integration, then regenerate project bindings with the rebuilt CLI. The advanced
surface includes gameplay. Runtime ABI 5, authoring ABI 6 and viewport ABI 14
remain unchanged by F8. Save-state scope is defined by ADR-0059; the combat
example saves selected gameplay data, not every engine execution detail.

Public publication still requires the owner's license decision in ADR-0005.


Physical-device diagnostic runs must be bounded and stop the exact process
launched for the test. Capture the process identifier using `devicectl device
process launch --json-output <file>` without console attachment, then terminate
that PID. Do not match all executables named `Runner`: unrelated Flutter apps
share that executable name. For native-console capture, identify the executable
by the installed diagnostic bundle's exact installation path before stopping it.
