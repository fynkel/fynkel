# Fynkel foundation roadmap

**Started:** 2026-09-30  
**Direction:** Accepted by the user in the foundation and ECS discussion.  
**Implementation:** Contract prototypes implemented; F1 identity (including host authority), clocks, affine transforms and conservative bounds implemented and verified. Earlier foundation fixes remain historical evidence.  
**Decision:** [ADR-0042](decisions/ADR-0042-ecs-centered-foundation-program.md)

This is the active roadmap and progress tracker for rebuilding Fynkel's foundations before expanding the product. The objective is one coherent gameplay model, an accessible object interface over an extensible ECS, and measurable runtime and tooling performance. Keep the Rust runtime, `hecs` facade, cooker, generated contracts, and transactional authoring where they satisfy the new contracts. Rebuild layers that do not. A complete rewrite is an option to evaluate, not a prerequisite.

The September 30 review inspected implementation and tests. Its performance concerns are hypotheses to measure; its correctness findings need reproducible tests. The attempted ECS/scene/core test run did not complete. This roadmap does not certify current code or invalidate earlier gate reports.

## Authority and progress

Accepted ADRs define architectural policy. This roadmap defines work order and completion criteria. Tests define observable behavior; gate reports record the revision and environment where that behavior was verified. Existing documentation describes the current implementation until a replacement is implemented. Proposed ADRs do not silently override accepted contracts.

The detailed replacements begin as ADR-0043 through ADR-0045. [ADR-0046](decisions/ADR-0046-transactional-world-state-replacement.md) selects transactional shared state; [ADR-0047](decisions/ADR-0047-identity-clocks-frame-order-and-readiness.md) resolves identity, clocks, frame order and readiness. General registry/delivery, effect policy and remaining qualification stay at their named gates before dependent implementation.

Use the task IDs below in implementation PRs and gate reports. The tables are the only task-status ledger for this program. Do not copy their status into other documents. Mark a task Done only when its acceptance criteria are verified, not just when code is merged.

| State | Meaning |
| --- | --- |
| Todo | No implementation evidence yet |
| Active | Work started; record owner and branch or PR |
| Blocked | Record dependency, reason, and next action |
| Done | Acceptance criteria and evidence linked |
| Deferred | Record explicit decision, destination milestone, and reason |

Tasks begin **Todo**, with owner unassigned and evidence absent. When work starts, add owner, state, and evidence in the Notes column. Evidence must identify a commit or PR and relevant test, benchmark, or gate result. In-progress working-tree evidence must say so explicitly. Reopen a task when its contract regresses. Current progress is **1 of 9 milestones complete**; do not present documentation creation as runtime progress.

The initial `World::edit_gameplay` API keeps only edited fields in a scoped native journal over the existing ECS. Invalid access/edit errors are sticky even when caught; explicit aborts and callback panics discard the journal. Commit propagates hierarchy/activity without a tick and publishes final parent events only; completed simulation snapshots stay at their recorded tick. Supported legacy staged commands are atomically adopted before entry, preventing later replay from silently overwriting a transaction. This restriction and between-tick render-history snapping are migration boundaries, not completion of F2.2/F2.3. No mutable Dart echo store, new ABI or performance claim is introduced. Structural edits now use distinct `PendingEntity` tokens scoped by world and transaction. Successful `EditCommit` reports resolve surviving spawns to live handles; canceled spawns never allocate, and abort retires all pending tokens. Destruction follows the staged hierarchy, preserving moved-out descendants and retiring moved-in ones. Frozen queries skip destroyed candidates and exclude later spawns. Creation mappings use the report rather than legacy wire temp IDs; final live reparent/destruction events still use the existing event stream. Component reads and writes now share catalogue-generated storage access and existing validators; Transform uses the same journal as its dedicated helper. Filtered query membership is frozen: replacement values are visible, while removal/re-addition requires a new query. Configuration survives disabled modules; subsystem effects reconcile at their existing phases. `Follow`, `ThirdPersonCamera`, and `Skin` now share their configuration declarations with scoped reference types. Component reads return `GameplayComponentValue`; writes accept it or convert an existing native value. Pending references resolve only after successful allocation. Invalid newly written targets fail the edit; final validation runs before allocation, while unchanged stored references retain existing weak-reference semantics. The [binary session protocol](design/foundation-gameplay-wire.md) now connects the same journal to an internal Dart synchronous callback. Owned sessions exclude legacy native mutations, retain no borrow across FFI, and restore the world on commit/abort. Explicit `World.edit` now routes ordinary GameObject operations through this boundary and reconciles caches and handles after commit. It rejects invalid legacy adoption and unported side effects; completed snapshots remain unchanged. The later SDK retirement batch removes outside-scope overlays and simulation queues; ordinary calls now open the same transaction. Explicit behaviour attachment is now transactional, with deferred callbacks and rollback-safe ownership. Behaviour enable/destroy is now transactional too, with coalesced requests and deferred cleanup. Object construction now participates in the journal. Body/character effects now publish commit-controlled requests for the next eligible physics tick, using shared configuration validation. Automatic callback and persistent presentation routing now use that authority. Next: migrate remaining guarded effects/resources and retire the superseded state path.

F0 records repeatable generators, durations, hardware tiers, warmup, and numerical budgets. Existing benchmark numbers are baselines only at their recorded revisions. Do not invent new frame-time guarantees without measuring them.

| --- | --- |

| Existing stress workload and a staged 50k-entity target | Native versus Dart work, extraction cost, bridge traffic, memory |

Benchmark realistic combinations, not just isolated subsystem throughput. Gate on reproducible correctness and budgets selected in F0, including tail latency.

## Change discipline

For each implementation change, identify its task, owning subsystem, contract, and verification. An architecture change updates or supersedes the relevant ADR in the same change; routine fixes within an accepted contract need no new decision. An ADR records context, decision, alternatives, consequences, status, migration, and evidence. Never label a detailed design Accepted just because a general direction was accepted.

For a milestone exit, create `docs/gates/foundation-fN.md` with exact revision, completed tasks, accepted decisions, reproducible validation commands, measurements, and remaining risks. Create these reports when evidence exists, not as empty success reports. CI should enforce generated-schema consistency, contract suites, runtime dependency isolation, and agreed regression budgets. Test concurrency and machine contention must be recorded when interpreting results.

Keep the old path only as long as migration requires. Adapters forward to the canonical implementation; they must not maintain a second simulation. Choose incremental replacement or isolated rebuild in F0, then deliver complete vertical slices. Do not expand features to avoid finishing a difficult foundation milestone.
