Fynkel Engine — Architecture Atlas

A map of how the engine is built: its systems, how data flows between Rust and Dart, when each piece of code runs in a frame, which platforms each part runs on, and where the implementation is risky or wrong. It was built by reading the code (every crate, package, host and the editor) and cross-checking it against docs/foundation.md, the ADRs and the gate reports. It is meant to answer one question: is this foundation safe to build on, and what must be fixed first?

How to read it. Severity: C critical — a game hits it soon, or it corrupts/loses work or crashes · I important · m minor · W watch / decided later · ✓ fixed in the foundation pass. Where a finding matches a row in docs/foundation.md, its id (e.g. F3.1) is given and the severity is the one that row uses. Findings marked NEW are not in foundation.md yet. File references are path:line at this snapshot. The diagrams need an internet connection once to load Mermaid; the graph view and risk table do not.

The engine in one paragraph

Rust owns the world; Dart owns gameplay; Flutter is only a host and UI. fynkel_core::World is a library (ADR-0007): an hecs ECS behind fynkel_ecs, transforms and hierarchy in fynkel_scene, Rapier physics, animation, its own audio mixer, and a fixed 60 Hz tick. Every frame, a host calls it synchronously. Here that is Flutter's Ticker in FynkelGameView, the winit standalone host, or the headless test host. Dart behaviours (package:fynkel) never touch Rust memory directly. They write commands into a binary batch, call step() through dart:ffi, and read back a zero-copy snapshot of transforms plus an event buffer (ADR-0004). The renderer (fynkel_render, wgpu) reads an interpolated extract of the world and draws into a ring of IOSurfaces that Flutter composites as a texture without any CPU copy (ADR-0002, platform/apple). Content is strict JSON documents (scenes, prefabs, materials, shaders, controllers) that fynkel_import cooks into a content-addressed binary cache. The runtime never reads a source document. The editor is a Flutter desktop app built per project. It edits documents through a Rust authoring session (transactions, undo) and runs Play in its own process by compiling the game in (ADR-0021).

Verdict

Solid — build on it

  • The layering is clean and points one way (contracts → ecs → scene → core → wire/native → Dart). hecs is provably hidden.
  • Batched command/snapshot protocol, generated codecs, a schema fingerprint and byte fixtures shared by Rust and Dart.
  • Determinism: physics iterates in entity order, the audio engine is deterministic, and headless checksums hold.
  • Audio is real-time safe: SPSC rings, and a test proves the mixer does zero allocations.
  • The cooked container is bounds-checked, CRC'd and forbid(unsafe). The cache key is content-addressed and propagates through dependencies.
  • The authoring ABI and fynkel_native wrap every call in catch_unwind and poison instead of crashing.
  • The Animator state machine is pure and well tested.

Shaky — fix before scaling

  • Object cost: instantiate re-reads and re-parses the file on every call, propagate walks every node up to 6× per tick, and refresh_active walks the whole tree.
  • Prefab-internal references resolve by name, world-wide.
  • Physics: one Rapier body per entity (no compound), and a body is rebuilt on any collider, layer or scale change.
  • Everything runs on one thread: gameplay, physics, extract, render encode, editor cook, asset decode.
  • God objects: the Rust World (~40–59 fields, a 235-line step()), Dart's world.dart (3,632 lines), the editor's app.dart (3,303), and fynkel_render/lib.rs (5,737).

Unsafe — fix first

  • platform/apple: 22 extern "C" functions with zero catch_unwind and 18 lock().unwrap(). A panic there aborts the app or editor.
  • After World.dispose(), Dart's snapshot view still points into freed native memory (a use-after-free).
  • A poisoned world throws every frame, forever.
  • Two live &mut to one world in input_view/drain_events (undefined behaviour).
  • One shared query buffer: a held query view can silently change to another query's bytes.
  • One missing asset fails the cook of every document that depends on it.

The entity handle

Defined in fynkel_contracts/src/handle.rs: 64 bits, packed. 0 is NULL. A temp handle (world = 0, generation = 0) names an entity spawned in the same batch and is resolved inside World::resolve_temps (world.rs:912).

Hierarchy & active state

How it works

  • Parent(Entity) + Children(Vec), changed only through fynkel_scene functions. is_ancestor rejects cycles.
  • Writing a Transform marks it dirty. propagate() is the only function that recomputes world matrices.
  • InactiveSelf (own flag) and Inactive (derived, i.e. !activeInHierarchy) are recomputed by refresh_active().
  • Names are a plain Name(String), not indexed. find/findWithTag is one EntityInfo query per tick followed by a linear scan.

What's wrong

  • C propagate (fynkel_scene/src/lib.rs:463) collects every root and pushes every child. Its doc says "dirty subtrees only", but it only skips the multiply. It is called at 6 sites in world.rs (733, 1057, 1463, 1485, 1498, 1519): up to 4× per tick, plus once per keep-world SetParent command. F3.3
  • I refresh_active does a full BFS from all roots as soon as any object is inactive. F3.4
  • C Named targets (Follow.target, camera targets) resolve to the first match world-wide, so two prefab instances bind to the same "Head". A miss costs an O(N) string scan every tick. F3.5
  • I fynkel_scene has 5 tests but owns the most-called code in the runtime. F6.5

4 · The frame & the tick — execution order and time

4.1 One frame, end to end (Flutter host)

Everything from the vsync tick to queue.submit() runs synchronously on the Flutter UI thread. Only GPU completion (a Metal completion handler) and texture acquire (the raster thread) happen elsewhere.

Lanes (ADR-0008 + the 2026-09-27 amendment): a transform write made in fixedUpdate or outside a frame is a simulation command, applied at the next tick. On an object's first write each tick that costs one native components query, cached for the rest of the tick. It is cheap but not free, and nothing measures it for many objects moved in update.

5 · The Rust ↔ Dart bridge

5.1 Wire format (ADR-0004, crates/fynkel_native/src/buffer.rs)

Every buffer that crosses the ABI starts with a 24-byte header. After it come the records, each at its field's natural alignment and padded to 8, followed by a string tail.

magic "FYNK" u32
abi u16
kind u16
record_count u32
byte_length u32
records_end u32
request_id u32

Buffer kinds

Commands 1 · Snapshot 2 · Events 3 · Diagnostics 4 · Query 5 · InputEvents 6 · InputActions 7 · PhysicsQueries 8 · ProjectionAnchors 9. A malformed header rejects the whole buffer (Status::Protocol) before any record is applied.

Commands (13 kinds)

Spawn · Destroy · SetTransform · SetParent · SetName · SetComponent · RemoveComponent · Body · Animate · Audio · PlaySound · AudioBus · SetActive. Each is {kind:u32,size:u32} + body. SetComponent = entity + raw component bytes. One bad command is rejected with its index and the rest still apply.

Versioning

ABI_VERSION = 1 (never bumped, despite many additive changes). SCHEMA_FINGERPRINT = 0xd21b7fb595a078a6 is an FNV-1a hash over every schema's canonical text and is checked when Dart opens the library. The viewport ABI (v4) and authoring ABI (v3) are versioned separately.

5.2 FFI calls per frame

The minimum for a frame with one tick is 7 calls: begin_frame, capture_input, drain_events, submit_commands(sim), step, drain_events, submit_commands(pres). Then fynkel_apple_viewport_render. On top of that come on-demand queries, each one a synchronous call: 15 kinds, including components, body state, character, animator, audio, physics raycasts and projection. The components query runs once per object per tick on first access.

Good

No per-frame native allocation in steady state: scratch buffers are reused and _ViewCache skips re-wrapping. Native never hands Dart memory that Dart must free.

Bad

C F4.2 World.dispose() frees the FynkelWorld, but _snapshot still wraps freed memory, so any GameObject kept past dispose reads freed heap.
m F4.9 One query_buf serves the components, physics and projection queries. A WireBuffer held across a second query silently shows the second query's bytes. The Dart cache only notices when the address or length changes.
I F4.4 fynkel_world_subscribe has no unsubscribe. Every entity Dart ever touches stays in the snapshot at 88 B per tick, and step() walks all of them. FYN-R0013 only warns.

6 · Physics — fynkel_physics (Rapier 0.35)

How it works

  • One Entry per entity with RigidBody/Collider/CharacterController, kept in a BTreeMap for deterministic order (a test proves bit-identical runs).
  • Ownership: dynamic body = physics owns it (a presentation write is rejected, code 9; a sim write teleports). Kinematic/character = gameplay owns it, and physics pushes toward the target. Static = moves with its entity. An external move is detected by comparing world matrices.
  • Sync (sim.rs:509-703) runs every tick: a full archetype query plus a "same?" predicate. It is 0.64 ms for 5,541 colliders at rest and 2.0 ms when 5,000 statics move.
  • Events: enter/exit exact; stay is opt-in per watched entity. Collector is a Mutex<Vec> (unneeded; Rapier forces &self).
  • Character controller: hand-written on Rapier's KCC with ~6 tuned epsilons (REST_PROBE 1e-4, GROUND_PROBE 0.05…).
  • Queries: ray/shape/overlap against the last stepped state. Mesh colliders are static only, max 32,768 triangles.
  • Materials (ADR-0025): one friction, combine rules.

Risks

  • C F2.1 No compound bodies. A child Collider under a dynamic parent becomes a separate fixed collider: one tick behind, no mass, and it can collide with its own parent. docs/physics.md actually recommends child entities for multiple colliders. ADR-0034 (proposed, awaiting your confirmation) fixes it, and tests/compound.rs measures the fall (y −75 instead of 1.5).
  • I F2.2 A collider, layer or scale change (relative epsilon 1e-4, sim.rs:615) rebuilds the body: velocity and sleep are lost and a false Exit→Enter fires. A scale tween on a collider rebuilds it every tick, silently.
  • I F2.3 no OnTriggerStay · F2.4 the character reports no hits · F2.5 no axis constraints · F2.6 Exit on destroy untested
  • I NEW No moving-platform carry. A platform pushed into a standing character tunnels (physics.md:387).
  • m NEW 63 index/unwrap sites in sim.rs trust the bookkeeping invariants, and there is no guard around Physics::step. One bookkeeping bug panics the step and poisons the world.
  • m NEW Character epsilons have outcome tests on a single scene only. A Rapier upgrade or a timestep change could silently bring back the "shoved into the floor" bug.
  • ⏸ F2.12 no joints, ForceMode, AddForceAtPosition or convex mesh colliders. Ragdolls, vehicles and doors are blocked.
  • Tests: 17 for a 2,739-line sim.rs (F6.5).

7 · Animation — fynkel_animation + fynkel_core/world/animation.rs

How it works

  • Clip = channels targeting nodes by name, resolved per instance and cached until the clip switches or a target dies.
  • Pose = a flat Vec<PoseEntry> with linear lookup; fine up to Skin::MAX_JOINTS = 256.
  • Runs at tick step 4, before physics, and writes Transform via set_local only when it changed. Fully serial, even though posing each animator is independent work.
  • Animator Controller (ADR-0032, controller.rs): a pure state machine with no ECS types. 17 tests: triggers, Any State, exit time per lap, interruption, determinism.
  • Animation v2 (ADR-0033): blend trees, code-built clips (ClipBuilder), IK (TwoBone/LookAt/FootPlacement in world/ik.rs).
  • Root motion: planar translation + yaw only (Y-up). The clip's vertical motion is dropped for character-driven entities.
  • Skinned render path: joint palette storage buffer, grows by doubling.

Risks & gaps

  • I NEW Name-based target resolution has the same shape as F3.5: duplicated bone or node names inside one hierarchy resolve to the first match.
  • m A trigger nothing consumes stays set forever. This matches Unity but produces phantom transitions much later.
  • m Clips are f32 keys, uncompressed. No retargeting, morph targets, 2D blend spaces, or root motion from non-primary layers (documented V1 gaps).
  • W The IK solver world/ik.rs is not audited here. FootPlacement couples to physics.
  • Tests: 30 in the crate plus the core's animation tests. The 200-rig gate is < 1 ms.

  • 30 built-in pipelines are created up front, with no compiles at draw time. Each .shader asset adds 18 pipelines on first use (naga assembles its surface() WGSL).

  • GPU memory is a hand-kept estimate (gpu_bytes()). Metal pass timestamps lag 3–4 frames.

  • C F4.3 The viewport ABI has no catch_unwind (verified: 0 in platform/apple/src). Every frame the game and the editor call prepare/draw through it, so any panic there aborts the process.
  • C NEW 18 lock().unwrap() calls in ring.rs, and all viewports share one wgpu Device (a SHARED_GPU global since ADR-0030). One poisoned mutex takes down every viewport: the Scene view, the Game view and the Inspector previews.
  • I F6.3 lib.rs is 5,737 lines, with prepare ≈ 900 lines and draw ≈ 1,150. There is no render-graph abstraction, and every pass is a manual if.
  • I F5.5 No texture compression (RGBA8/RGBA16F only). A 4K texture ≈ 85 MB. This blocks iOS.
  • m Per-cascade shadow caster culling is not done. The shadow cost ≈ 4× going from 1 to 4 cascades.
  • m Normals use the model matrix, not the inverse-transpose, so they are wrong under non-uniform scale. Transparency is sorted per object.
  • m read_frame waits for the GPU to go idle. Nothing stops it being called every frame.
  • m NEW World::extract() allocates a Vec<Entity> and a HashMap every frame (world.rs:1987, 1995). The rest of the code carefully reuses scratch buffers.

Prefabs

  • A scene entity with prefab:{asset, instance, overrides[]} is the prefab's root (ADR-0022). Override ops: setField, unsetField, add/removeComponent, add/removeObject, setActive, all addressed by prefab-local ids.

  • I NEW God file: app.dart (3,303 lines), plus nine more files over 1,200 lines.

  • m Native Inspector hints are a hand-kept Dart table (E9). The compile_error_parity test is flaky (F0.5), and the play_process kill -9 test is flaky on a cold build.

16 · What to fix before building more — recommended order

This order puts anything that crashes, corrupts or loses work first, then anything whose cost grows with every asset and every line of game code, then structure. It mostly agrees with foundation.md's Step 1–6 order. Where it differs, the reason is given.

Wave A — crash safety (days, not weeks) C

  1. F4.3 + ring mutexes: wrap all 22 fynkel_apple_* in the same guarded() pattern fynkel_native uses. Replace lock().unwrap() with poison-tolerant locking. Add a panic-injection test per entry point. (Move this ahead of Step 2: it is the one bug that kills the editor.)
  2. F4.1: FynkelGameView._frame try/catch; check isPoisoned once; show an error widget; stop ticking.
  3. F4.2: World.dispose nulls _snapshot/_snapshotIndex and marks every GameObject dead, so a read afterwards throws.
  4. F4.5: remove the double &mut by returning the view from inside the guarded closure. Run Miri over fynkel_native in CI.
  5. F4.9: one buffer per query kind, or invalidate held WireBuffers (a generation counter checked on read, in debug builds).

Wave B — objects at scale C

  1. F3.9 first: the 50k-entity headless benchmark and a spawn-rate benchmark. Measure before fixing.
  2. F3.3: a true dirty-subtree propagate (a dirty-root list), and fold the 4 per-tick calls into 1–2.
  3. F3.1: cache a spawn-ready template per prefab: no re-read, re-validate or re-register per instantiate; residency per template, not per call. Then add pooling guidance (F3.2).
  4. F3.5: resolve named targets per prefab instance at instantiate time (entity refs, like Unity), and index names.
  5. F3.4 incremental active refresh; F4.4 unsubscribe on destroy and drop untouched handles.

Wave C — content never breaks the game C/I

  1. F5.1: a missing reference becomes a warning plus an empty field, and the cook continues.
  2. F3.8: a stale override is kept and listed; the instance still loads.
  3. F5.2: detect duplicate GUIDs on scan and re-id the newer file.
  4. F2.1: compound bodies (ADR-0034 is drafted — confirm it). Child colliders join the nearest parent body. Do it before content relies on the current behaviour, which physics.md recommends today.
  5. F2.2: update the collider in place and keep velocity. No rebuild on scale.

Wave D — threads & structure I

  1. Editor: move recook/openProject/validate off the UI isolate (a worker thread on the Rust side, with a progress callback). Parallelise the cook per asset (F5.3). Add autosave (F1).
  2. Runtime: an async/preload path for decode (F5.4) before any level streaming.
  3. F6.1: split the Rust World into subsystem states behind an ordered system trait, and generate SYSTEMS from it. Do the same with Dart's world.dart.
  4. F6.2: generate the ComponentValue arms, the bridge::query arm and the editor hints from the schema registry.
  5. F6.3: split fynkel_render/lib.rs by pass. F6.4: a runtime-only crate that doesn't link fynkel_document.
  6. F6.5: tests for fynkel_scene (property tests: random hierarchies, reparent, destroy mid-walk), fynkel_physics, fynkel_assets, fynkel_editor_api.
Rule for new features until Waves A–B are done: nothing new that spawns at runtime (projectiles, particles, crowds), relies on child colliders, or adds another extern "C" surface. Those are exactly the paths where the current foundation is weakest.

17 · Glossary

Host
Whatever owns the loop and calls the engine: Flutter's FynkelGameView, the winit standalone host, the headless host, the editor's Scene view.
Tick / step
One fixed simulation step (1/60 s) inside World::step(). A frame runs 0–4 of them.
Frame
One host frame (vsync). update/lateUpdate run once per frame.
Simulation lane
Commands applied at the next tick boundary.
Presentation lane
Commands applied immediately, for this frame's picture only; transform writes are also taken by the next tick.
Snapshot
The per-tick buffer of transforms for subscribed entities, read by Dart zero-copy.
Extract
The renderer's per-frame view of the world, interpolated by alpha.
Cook
Turning source documents and imported files into the content-addressed .fyna cache the runtime reads.
Residency
Which cooked assets are held in memory; retain returns an RAII token.
Poisoned
A world or session that caught a panic. Every later call refuses; the host must destroy and recreate it.
Catalogue
Native, Behaviour-free components for bulk motion: Rotator, Oscillate, Follow, LookAtCamera, LifetimeDespawn, Emitter.
Fingerprint
A hash of every wire schema. Dart and the cache refuse a native library or cache built with a different one.
