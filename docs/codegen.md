# Schema codegen (ADR-0012)

## Native pipeline (a)

Rust structs are the source of truth for every record that crosses the bridge.

```text
#[derive(Schema)] structs                      fynkel_core::schema::ALL (registry)
  fynkel_scene::Transform, fynkel_core::Name,          │
  fynkel_core::components::{Camera, MeshRenderer, …}   │
  fynkel_core::schema::{*Command, *Event, *Record}     ▼
                                              `fynkel codegen`  (apps/cli)
                                                       │
        ┌──────────────────────────────┬───────────────┴───────────────┐
        ▼                              ▼                               ▼
 schemas/fynkel.schema.json    packages/fynkel/lib/generated/   crates/fynkel_wire/src/generated.rs
 schemas/components/*.json     schema.g.dart (Dart codecs,      (Rust codecs, SCHEMA_FINGERPRINT,
 schemas/scene.schema.json      copyWith, componentCodecs/Ids)   ComponentValue wire dispatch)
 schemas/settings.schema.json
                                                                crates/fynkel_document/src/generated.rs
                                                                (JSON ↔ typed component codecs,
                                                                 embedded schemas, ComponentValue dispatch)
```

* `fynkel_contracts::schema` defines the metadata (`RecordSchema`, `FieldType`), the wire layout rule (little-endian, natural alignment, records padded to 8, strings as `(offset, len)` into a string tail) and the fingerprint (FNV-1a over the canonical text of the registry).
* `fynkel_schema_derive` provides `#[derive(Schema)]` with `#[schema(kind = "component" | "command" | "event" | "record", id = N, name = "fynkel.X")]`. Supported field types: `f32 u32 i32 u64 bool Vec3 Vec4 Quat Entity Option<Entity> String AssetRef Option<AssetRef>`, nested schema structs, and unit-variant enums that also `#[derive(Schema)]` (`#[schema(name = "fynkel.Projection")]`). An enum is a `u32` declaration index on the wire and the lowerCamel variant name in JSON (`"perspective"`) and Dart (`Projection.perspective`); the variant list is part of the fingerprint, so append only. `AssetRef` is 16 id bytes + `sub` as a wire string (24 bytes), `{ "asset": uuid, "sub"? }` in JSON (`envelope.schema.json#/$defs/assetRef`), and `AssetRef(asset, sub:)` in Dart; `Option<AssetRef>` is the same 24 bytes with a nil id for `None`, `assetRef | null` in JSON (never required) and `AssetRef?` in Dart; `Vec4` is 16 bytes / a 4-number array; an unknown enum index or malformed id fails decoding/encoding loudly on both sides. Doc comments flow into JSON Schema and Dart docs. A built-in authored component's Dart constructor gives every field the value of its Rust `Default` (`fynkel_authoring::component_default`, what Add Component writes; ADR-0026 §6), so `const RigidBody()` is a dynamic 1 kg body and `RigidBody(mass: 5)` names one field; a component without a `Default` (`fynkel.Name`), and every record, command and event, keeps `required` fields; defaults are Dart-only and do not move the fingerprint. `authored = false` marks runtime-only records (`fynkel.Name`): they get no `data` binding in `scene.schema.json` and scene validation rejects them (`FYN-D0207`). `document = "<kind>"` on a `record` marks a **document record** — the top level of a document kind (`fynkel.PbrMaterial` → `.material.json`, M3-02): every field is optional in the document and takes the Rust `Default` (the generated `from_node` reads through `or_default`; `generated::document_defaults()` exposes the defaults so the schema carries them as `default`), and codegen writes `schemas/<kind>.schema.json` from it (for material: the envelope, `shader`, the record's fields, plus the custom-shader `parameters`/`textures` groups and the `$defs` they need; `x-fynkel.document` names the kind). `document` is not part of the fingerprint; the record's wire layout is.
* Generated files are **committed**. `cargo test -p fynkel_cli` runs `fynkel codegen --check` and fails on drift; regenerate with `cargo run -p fynkel_cli -- codegen`.
* Protocol fixtures: `tests/fixtures/wire/<fingerprint>/<Record>.bin` are written by the Rust codecs (`FYNKEL_UPDATE_FIXTURES=1 cargo test -p fynkel_wire`) and decoded + re-encoded byte-for-byte by the Dart codecs (`dart test` in `packages/fynkel`). A schema change produces a new fingerprint directory; delete the old one in the same commit.

## Behaviour generator (ADR-0012 pipeline (b), M2-16)

The game's Dart classes are the source of truth for behaviour types. Nothing
is discovered at runtime and nothing uses mirrors: a `build_runner` builder
in `packages/fynkel_generator` turns every `@FynkelBehaviour` class into
ordinary Dart the game registers explicitly, plus the JSON Schemas the
document layer validates scene data against.

```text
@FynkelBehaviour(id: 'game.Spinner') class Spinner extends Behaviour {
  @Expose(min: 0, step: 0.1) double speed = 1.0;              lib/**.dart of the game package
  @Expose() Vec3 axis = Vec3.up; …                                    │
}                                                                     ▼
                              `fynkel codegen --project <package>`  → `dart run build_runner build`
                                                                      │
              ┌───────────────────────────────────────────────────────┴──────────────┐
              ▼                                                                      ▼
 lib/generated/behaviours.g.dart                                    lib/generated/behaviours.g.json
   gameSpinnerType = BehaviourType(id, version, create,               per type: id, version, class, library,
     fields: [BehaviourField(name, type, defaultValue,                fields (type, default, min/max/step,
       min/max/step/label/tooltip, get, set)])                        label/tooltip, description) + `schema`
   behaviourTypes, registerBehaviours(registry)                                    │  (split by the CLI)
                                                                                   ▼
                                                                    schemas/behaviours/<id>.schema.json
```

* **Package:** `packages/fynkel_generator` (deps `build`, `source_gen`, `analyzer`, `dart_style`, `glob`). Its `build.yaml` auto-applies the `behaviours` builder to every package that depends on `fynkel_generator` (a dev dependency of the game), `build_to: source`. The builder is an aggregate over the placeholder input `$lib$`: it resolves every library under `lib/` (skipping `lib/generated/` and `*.g.dart`), reads the annotations through `source_gen`'s `TypeChecker`/`ConstantReader` and the analyzer's element model, reads field initializers from the AST for defaults, and writes the two outputs once per package. Output is sorted by type id and formatted with `dart_style`, so it is byte-stable.
* **Rules the builder enforces (build errors that name the file and member):** the class extends `Behaviour`, is public and concrete, has an unnamed constructor without required parameters; `id` is namespaced (`game.Spinner`; `fynkel.` is reserved) and unique in the package; `version >= 1`; an `@Expose` field is a public, assignable instance field (inherited fields up to `Behaviour` count too) of type `double`, `int`, `bool`, `String`, `Vec3`, `Quat`, `AssetRef`, `List<Vec3>` or `List<T>` (ADR-0027 §5: `T` a non-nullable `double`, `int`, `bool`, `String`, `Quat`, `AssetRef` or enum), optionally nullable, a public Dart `enum`, `GameObject?`, or a nullable `@FynkelBehaviour` class (a reference must be nullable; ADR-0018 amendment 2026-09-24), or a nullable `@FynkelDataAsset` class or a `List` of one (ADR-0027 §4); an `@Expose(kind:)` fits the field's type (`color` on a `Vec3`, `asset(<kind>)` on an `AssetRef` or a `List<AssetRef>` with a known kind, `entity`/`multiline` on a `String`, `angle` on a `double`, `slider` on a `double`/`int`, `layerMask` on an `int`) and `showIf` names another exposed `bool` of the class; a `drawer` is one word (letters, digits, `_`, `.`); a `@Gizmo` sits on an `@Expose` field of the type its shape draws (`radius` a `double`/`int`, `box`/`point`/`direction` a `Vec3`, `cone` a `double` length whose `angle:` names another exposed `double`, `lineTo` a `String`, `path` a `List<Vec3>`).
* **Field wire form** (`BehaviourField.type` / schema): `double` ↔ `number`, `int` ↔ `integer` (a non-integral JSON number is rejected), `bool` ↔ `boolean`, `String` ↔ `string`, `Vec3` ↔ `vec3` = `[x, y, z]`, `Quat` ↔ `quat` = `[x, y, z, w]`, `AssetRef` ↔ `assetRef` = `envelope.schema.json#/$defs/assetRef`, `List<Vec3>` ↔ `vec3List` = `[[x, y, z], …]` (item 9h, for `@Gizmo.path`; a list literal of `Vec3` literals is a default). `List<T>` ↔ `list` = a JSON array of `T`'s form (ADR-0027 §5; `x-fynkel.items` names `T`'s type word, and the schema's `items` carries the item's own schema and hints — `min`, `max`, `step`, `unit`, `kind` describe each item, so a `List<AssetRef>`'s `asset(<kind>)` sits on its `items`); `get` answers a fresh `List<Object?>`, never the live list, and `set` builds a new growable list; a list literal of item literals is a default. An `enum` ↔ `enum` = the value's name (the schema lists the names; `Mode.fast` is a default). `GameObject?` ↔ `gameObject` = `{ "entity": id }` and a script class ↔ `behaviour` = `{ "entity": id, "component": id }` (`x-fynkel.behaviour` names its type id): their `get` answers that JSON (`referenceJson`: the id the editor's live table shows, else the authoring id, else `runtime:<handle>`), but their `set` takes the resolved object — `BehaviourRegistry.instantiate` skips them, and the world sets them once every behaviour of the load is attached, through the load report's per-behaviour `references` (authoring id → spawned handle); a target that is not there leaves the field null with `FYN-B0003`. `get` returns the JSON form, `set` converts from it and throws on a value that does not fit (the registry wraps that in `BehaviourDataError`). A literal initializer (`1.0`, `-2`, `true`, `'x'`, `Vec3(0, 1, 0)`, `Vec3.up`, `Quat.identity`, `AssetRef('…', sub: '…')`, `AssetRef.none`, `null`) becomes `defaultValue` and the schema's `default`; any other initializer still applies at runtime (the class sets it) but is not in the metadata.
* **Schema:** `schemas/behaviours/<id>.schema.json` is a JSON Schema 2020-12 for the component's `data` — every field optional (the class default applies), `additionalProperties: false`, `minimum`/`maximum` from `@Expose(min:, max:)` on numbers, nullable fields as `["number", "null"]` (or `anyOf` with `null` for `assetRef`), Inspector metadata under each property's `x-fynkel` (`type`, `nullable`, then every hint given: `label`, `tooltip`, `min`, `max`, `step`, and the ADR-0018 set — `group`, `order`, `header`, `unit`, `kind` (`color`, `asset(<kind>)` with `<kind>` one of `texture`, `material`, `mesh`, `prefab`, `scene`, `audio` (the editor's `sound`), `clip`, `skin`, `rig`, `volume`, `physics_material`; a reference of another kind is `FYN-A0007` in `fynkel validate` and the cook; `entity`, `multiline`, `angle`, `slider`, `layerMask`), `readOnly`, `hidden`, `showIf` (`"<field>"` / `"!<field>"`), `drawer` (ADR-0028: the property drawer an editor extension registers under that name; on a `List`, on its `items`), and ADR-0019's `gizmo: { shape, angle?, color?, when?, space? }` from `@Gizmo.<shape>(…)` (`color` an `0xAARRGGBB` integer; `when: "always"` and `space: "world"` only when not the default) — written only when set, so an unhinted class emits exactly what it did before M4-04) and the type's identity under the document's `x-fynkel: { kind: "behaviour", id, version, dart: "package:…#Class", icon?, category? }` (`@FynkelBehaviour(icon:, category:, description:)`; `description` replaces the class doc comment as the type's description). `behaviours.g.json` carries the same hints per field and `icon`/`category` per type. The editor's Inspector reads them as data (docs/editor.md § The Inspector). `fynkel_document` loads a project's `schemas/` directory on top of the embedded schemas (`SchemaSet::embedded_with`, `Project::schemas`), so `fynkel validate`, the cooker and every project-aware command know the type, validate its data (`FYN-D0206`) and stop reporting it as unknown (`FYN-D0205`). A registry entry of kind `behaviour` in `fynkel.project.json` declares a type without a schema (`SchemaSet::declare_behaviour`): known, data accepted as any object.
* **CLI:** `fynkel codegen --project <dart package> [--check]` runs pipeline (a) as before and then (b): `dart pub get` when the package has no `.dart_tool/package_config.json`, `dart run build_runner build`, then the split into `schemas/behaviours/` and, for data types, `schemas/data/` (stale `<id>.schema.json` files removed from both). The Dart SDK is `$FYNKEL_DART`, else the `dart` next to `flutter` on `PATH`, else `dart` on `PATH`. `--check` runs the generator too, compares the three outputs and the schema directory, puts the committed generated files back and exits 2 on drift. The two pipelines have separate caches: (a) has none (a pure function of the Rust registry), (b) is build_runner's `.dart_tool/build`. Both outputs are **committed** in the game package.
* **Asset constants (ADR-0026 §3, 2026-09-25):** for a package beside a `fynkel.project.json`, `fynkel codegen --project` also writes `lib/generated/assets.g.dart` (`apps/cli/src/assets_gen.rs`) from the same asset database `fynkel validate` scans: `abstract final class Assets` with one static const per top folder or file under `assets/`, a folder a const object whose getters are its members, a file an `AssetRef` getter holding its **id**, and a file with sub-assets a group — `asset`, `prefab` (`sub: 'prefab'`), and `meshes`, `materials`, `images`, `skins`, `clips` by name — so game code writes `Assets.prefabs.burst`, `Assets.models.robot.meshes.cube`. Names are lowerCamel stems (`step_left.ogg` → `stepLeft`), a Dart keyword or leading digit gets a `$`, a folder keeps a name it shares with a file (the file gets its extension, `heroGlb`), then numbers. Getters, not consts (Dart has no nested types): `final menu = Assets.scenes.menu;`. `--check` compares it with the rest; `--assets-only` does only this, without build_runner (JSON `{ ok, check, assets: { status } }`, `status` `written` / `upToDate` / `stale` / `skipped` / `error`) — the editor runs it after assets change, and `fynkel create` writes it. A git-excluded local asset lands in it too: generate from the tracked files before committing.
* **Animator wrappers (ADR-0033 § 3, 2026-09-26):** beside it, `lib/generated/animators.g.dart` (`apps/cli/src/animators_gen.rs`) gives every Animator Controller of the project typed access, named after the file (`player.controller.json` → `Player`, a number for a second of the same name): `extension type const PlayerAnimator(AnimationControl animation)` with a `double`/`int`/`bool` getter and setter per parameter, a method and `reset…` per trigger, `state`/`nextState` as the base layer's `PlayerState` enum (another layer with states gets `Player<Layer>State` and a `<layer>State` getter), typed `play`/`crossfade`, and `playOneShot`/`stopOneShot`/`isPlayingOneShot` taking a `PlayerSlot`. A parameter named like a member gets `Parameter` (`stateParameter`); enum values avoid `name`/`index`/`values`. Written by `--project` and `--assets-only` (so the editor rewrites it after a controller is saved), compared by `--check`; no file without controllers, an emptied one after the last is removed.

* **Data types (ADR-0027 step 3):** a class annotated `@FynkelDataAsset(id:, version:, menu:, icon:, description:)` that extends `DataAsset` is a data type — Unity's ScriptableObject. The builder reads it with the behaviours (one id space for both) under the same rules, except that it extends `DataAsset`, and that `GameObject?` and script fields are a build error on it (an asset cannot point into a scene), as is a `@Gizmo`. It emits a `DataType` (`id`, `version`, `create`, `DataField`s with the behaviour fields' shape over a `DataAsset`) per class, `dataTypes`, and `registerBehaviours(registry)` registers them too (`BehaviourRegistry.registerData`, `lookupData`, `dataTypeOf`, `instantiateData`, which throws `DataAssetError`), so a game needs no new call; a game without data types gets the same generated file as before. `behaviours.g.json` lists them under `dataTypes` with `menu`, `icon` and `description`, and the CLI splits their schemas into `schemas/data/<id>.schema.json` (`$id` `…/schemas/data/<id>.schema.json`, `x-fynkel { kind: data, id, version, dart, menu?, icon? }`), which `fynkel_document` loads by type id to check `.data.json` assets ([documents.md](documents.md) § Data assets). The CLI reports `N behaviour types, M data types`; its `--json` gives `types` (behaviours) and `dataTypes`. A default can also be the unnamed constructor's `this.<field> = <literal>` (`Weapon({this.damage = 1})`), for any class.
* **Data-typed fields (ADR-0027 §4):** a nullable `@FynkelDataAsset` class (`Weapon? weapon`), or a `List<Weapon>`, on a behaviour or a data type ↔ `data` = `{ "asset": id }` (the schema's `anyOf` of the envelope's `assetRef` and `null`, `x-fynkel { type: data, data: <type id> }`; a list's `items` carry the same). `BehaviourField.dataType` / `DataField.dataType` name the type (`holdsData`). `get` answers the instance's asset (`dataJson`: null for none or for an instance made in code), `target` the instance, and `set` takes the resolved instance: the registry skips these fields and the world resolves them to the shared instance at load (`World.data`; a reference that cannot be made is None with `FYN-B0004`; [documents.md](documents.md) § Data assets). `GameObject.clone` shares the instance, it does not copy it. `fynkel validate` reports a reference to anything but a data asset of that type as `FYN-A0007`.
* **Records (ADR-0027 §5, step 7):** a plain class annotated `@FynkelRecord()` (Unity's `[Serializable]` class) is a nested value: a behaviour, a data type or another record exposes it alone (`Wave boss = Wave();`) or in a `List<Wave>` ↔ `record` = a JSON object of its `@Expose` fields (`x-fynkel { type: record, record: <class> }`; the schema inlines its `properties`, every key optional, `additionalProperties: false`; a list's `items` carry the same). The builder reads its fields under a type's rules and refuses a nullable record field (a record is a value: initialize it), a record that holds itself, even through a list (its schema would never end), `GameObject?`, script and data-typed fields in a record (it holds values only), and a `@Gizmo` on one. The generated file gets one helper pair per record class (`_wave(json)` builds a new instance, a key left out or a null for a field that cannot be null keeping the class default; `_waveJson(r)` answers every field), so a load, a clone or `set` makes new instances and a record has no identity. An initializer `Wave()` without arguments is the default `{}`; `Wave(count: 1)` still applies at runtime but is not in the metadata. The Inspector draws a record as a foldout ([editor.md](editor.md) § The Data page); the example is `spinner_game`'s `game.Spawner` with its `Wave` and `Spread` records.
