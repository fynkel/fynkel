# Fynkel Code Only

The acceptance game of ADR-0026 (docs/code-first.md in the engine): a small
level in the Playground's style — a player, five coins, a switch that raises
a gate, a sweeper that sends you back to the start, a HUD, Menu → Level →
Results — made from Dart alone. Nobody wrote a scene, a prefab or a material
by hand or with Python: the project's sources are a sky texture and five
sounds, and every document in `assets/` comes from the Dart specs.

```sh
flutter test                     # test/game_test.dart: the whole game headless, both ways (below), one input route collects every coin
fynkel run                       # validate, cook, then flutter run: the places built live
fynkel run --dart-define=CODE_ONLY_MODE=scenes   # the same game from the written scene documents
dart run tool/scenes.dart        # rewrite assets/ from the specs (then `fynkel cook`)
fynkel cook && fynkel render --scene 9f5c3884-502a-5d03-9eae-81593ede92a9 --out level.png
```

The project names no startup scene: `World.loadProject` opens it empty (the
input actions, layers, tags, gravity and cooked assets bound, no scene), and
the game puts its places in the world one of two ways, from the same specs:

- **Live** (the default). `lib/game/level.dart` describes the Menu, the Level
  and the Results as `ObjectSpec` trees; `LiveFlow` (`lib/game/game.dart`)
  makes the materials with `world.createMaterial` and each place with
  `world.build`, destroying the previous one.
- **Scenes**. `tool/scenes.dart` hands the same specs to
  `package:fynkel/authoring.dart`'s `ProjectWriter`, which writes
  `assets/materials/*.material.json`, `assets/prefabs/coin.prefab.json` and
  `assets/scenes/{menu,level,results}.scene.json`; `SceneFlow` loads them by
  id (`scenes.transition(Assets.scenes.level)`) as a game made in the editor
  would. The written documents open in the editor like any others, and
  objects added there survive the next `dart run tool/scenes.dart`.

The first test checks that the committed documents are what the tool writes
now; the rest run each way and compare the two levels object by object.

The coins come in two kinds (ADR-0027, data assets — Unity's
ScriptableObject): `CoinKind` (`lib/game/coin_kind.dart`) holds what a coin is
worth, its colour, size and sound. `tool/scenes.dart` writes the coin and the
big coin worth five as `assets/data/coin.data.json` and `big_coin.data.json`
(`ProjectWriter.writeData`) and a prefab per kind whose `Collectible` names
it; every coin of a kind shares its one instance, so an edit to the asset in
the editor's Inspector changes them all. Built live, the coins hold the same
kinds made in code. The last coin, behind the gate, is the big one.

Between the first two coins spins a gem: the prefab of the `pickups` package
(`examples/packages/pickups`, ADR-0029), a dependency in `pubspec.yaml`.
Its `Pickup` script, its `PickupKind` data type and its assets come with it —
the level places `pickups.Assets.prefabs.pickup` both ways, and the editor
shows the package's assets under Packages/pickups and its Tools ▸ Pickups
menu. `GameState` is the package's `PickupSink`: the gem adds its ten
points to the score, so the route scores 19.

Gameplay is four behaviours in `lib/game/`: `Player` (camera-relative walking
through a `CharacterController`, the jump, the clock, dying on the sweeper,
restart), `Collectible` (a trigger zone that scores its kind's value, plays its sound and builds
a burst of sparks in its colour), `Switch` (the prompt and the `interact` press) and `Gate`
(a `moveTo` tween). `GameState` is the HUD's model; `lib/main.dart` is the
Flutter overlay switching on `GameState.screen`.

`AGENTS.md` describes the layout, every command and the validate → codegen →
build → test loop for tools and AI agents.
